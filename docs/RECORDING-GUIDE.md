# Product recording guide

Record the actual supported Praxis application, not this website or a reconstructed browser interface.

1. Use a clean test profile, test accounts, and public pages. Remove personal names, tokens, private conversations, notifications, and unrelated desktop content.
2. Record the exact build/commit and platform. First verify the current top bar against `ASSET-RECORD.md`.
3. Rehearse a complete successful request using actions supported by that build. Preserve the actual assistant response and browser result. Do not substitute text or stage a fake execution.
4. Frame the application at its original aspect ratio with readable text. Move the pointer deliberately. Avoid unnecessary zooms or decorative camera movement.
5. Keep any confirmation step understandable. For workflows, show the conversation that creates/runs the task and communicate browser-open execution limits beside it when applicable.
6. Make a useful poster from the same recording. Supply English WebVTT captions and a full visible transcript. Voice clips must be understandable with audio muted.
7. Export an MP4 (H.264) and optionally WebM for a clean native player. Keep the dimensions accurate in the registry. Avoid an enormous high-resolution file when 1440p/1080p preserves readability.
8. Set `editedForLength: true` if pauses/steps have been shortened. The player shows that note. Editing is not a speed benchmark.
9. Add the recording only after inspecting the final file. Check caption timing, end state, original aspect ratio, and the absence of sensitive information.
10. Verify keyboard playback, Escape-to-close, focus restoration, captions, transcript, mobile sizing, reduced-motion, and data-saving behaviour in the website.

The optional hero loop checks reduced-motion, data-saving, page visibility, and intersection before starting. Main/feature videos use native controls and do not autoplay. Every configured recording must have a poster, captions, and transcript. Missing recordings do not create a fake player.
